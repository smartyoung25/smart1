## 0. 요약 (Executive Summary)

플랫폼의 **배선(frontend↔backend 계약)은 견고**하다 — 죽은 엔드포인트·메서드 불일치·응답필드 깨짐·데모 403 거짓성공이 **0건**(API 계약 에이전트 전수 확인). 즉 "안 돌아가서" 생기는 문제가 아니다.

문제는 전부 **① 시스템 로직**과 **② 내용 논리 일관성**에 있으며, 근본 원인이 **10대 테마**로 수렴한다. 특히 아래 5건은 운영 영향이 크다.

| 등급 | 원인 테마 | 핵심 증상 |
|:--:|---|---|
| 🔴 **CRIT** | A. 인증/세션 생명주기 | 캐시 토큰 무검증 재사용·갱신 0 → 만료/재기동 시 **전 화면 KPI 공백** |
| 🔴 **CRIT** | B. 타임존 KST/UTC 반쪽수정 | 운영 UTC 컨테이너에서 **P1~P6 관수 Period 9시간 오판**(절대변경금지 로직) |
| 🔴 **CRIT** | C. 이중 게이트·모델 서빙 | 게이트 탈락 작목이 **가짜 예측을 "신뢰도 높음"으로 서빙**(스케일러 누락 포함) |
| 🔴 **CRIT** | H. 보안 불변식 위반 | **전화/이메일(PII) 반환 GET**을 데모가 cross-farm 열람 가능("PII GET 0개" 위반) |
| 🔴 **CRIT** | K. 데이터 계층 | 커밋된 런타임 데이터가 **배포 시 iwinv 운영 실데이터를 덮어씀** · 가격 6~30배 단위 불일치 |

## 1. E2E 시뮬레이션 결과 (브라우저 실행)

로컬 서버(uvicorn:8055, PUBLIC_DEMO)로 가치사슬 전 구간을 실행 — 홈(C3)·ERP(C5)·생육(G4)·토양(F4)·챗봇(C13)·관제(C20).

- **렌더 건전성**: 편집·검수 대상 전 화면 **콘솔 에러 0**. 챗봇은 LLM 크레딧 소진 시 규칙기반 폴백으로 **정직하게** 응답(출처·"원문 발췌" 배지).
- **로컬 환경 사항(플랫폼 결함 아님)**: 로컬 DB 인증 실패 → in-memory 폴백(운영 iwinv는 db_ok 정상). health가 위험을 로깅.
- ★ **런타임 발견 4건**(아래 상세 E1~E4).

## 2. 근본 원인 테마별 상세

### 🔴 A. 인증/세션 생명주기 결함 (플랫폼 전역)

**원인**: 화면들이 데모/JWT 토큰을 sessionStorage에 캐시하고 `_ensureToken()`이 **검증 없이 그대로 반환**(`if(stored) return stored`). 공유 레이어 `components/data.js:46`는 `_token`을 **모듈 로드 시 1회만 캡처**하고 이후 재조회하지 않는다. 그리고 **401→토큰 재발급 로직이 전 코드에 0건**. SW(`sw.js:32-40`)는 `/api/` GET을 **상태무관 캐시**해 401·만료된 200을 재생한다.

| 증거 | 위치 |
|---|---|
| 캐시 토큰 무검증 반환 | 전 화면 `_ensureToken` (예: c3_home.html:657-675) |
| 공유 `_token` 1회 캡처·미갱신 | components/data.js:46 |
| `KaasaData.init` 미호출로 무인증 전송 | screens/c11_pool_join.html:129·189 |
| SW API 상태무관 캐시·재생 | sw.js:32-40 (HTML/정적 분기는 200 게이트, API 분기만 누락) |
| 데모 토큰 TTL | JWT_EXPIRE_MINUTES 기본 **60분** (auth.py) |

**E2E 재현(E1)**: 홈 로드 시 초기 200 → 이후 **~20개 엔드포인트 401 배치**(billing·environment·harvest·revenue·field·pdca…). JS 진단: 저장 토큰으로 `/environment` **401**, 새 토큰으로 **200**. → sessionStorage의 stale 토큰이 원인. 결과 화면: 내부온도·습도·CO₂·일사 **"—"**, 수확예측·매출·배액률·VPD **"—"**, PDCA **0%**, "센서 재연결 중…"(**인증 만료를 센서 문제로 오인 표시**).

**영향**: 첫 로드는 정상이나, **세션 60분 경과·서버 재배포·재기동 시 전 화면 데이터가 조용히 공백**이 되며 자동 복구가 없다. 반환 사용자가 반복적으로 겪는다.

### 🔴 B. 타임존 KST/UTC 반쪽 수정 (운영 P1~P6 오작동)

**원인**: `task_recommend.py`는 `now_kst()`로 하드닝됐으나(주석: "컨테이너는 UTC…Period가 9시간 어긋나 조용히 틀린다"), **같은 P1~P6 Period 선택을 먹이는 형제 모듈은 미수정**.

| 위치 | 문제 |
|---|---|
| api/services/climate_plan.py:513 | `active_setpoint()`가 naive `datetime.now().hour` → UTC 컨테이너 9h 오프셋 → 잘못된 Period의 "지금 목표값" |
| api/services/pdca.py:349 | `_today_plan()` naive `now().hour` → PDCA "오늘의 계획" 동일 오류 |
| pipeline/kamis_fetcher.py:327 | `now_kst.hour`(KST) + `date.today()`(UTC) 혼용 → KST 00~09시 KAMIS 캐시 날짜 오판 |

**영향**: CLAUDE.md가 **"절대 변경 금지"**로 못박은 P1~P6 관수 Period가 **운영 UTC 컨테이너에서 하루 ~9시간 잘못된 daypart**로 판정된다. 로컬(KST)에서는 재현되지 않아 은폐된다. G2 목표값·PDCA 계획·avg24 baseline에 파급.
