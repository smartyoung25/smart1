# 스마트팜 수익성 향상 플랫폼 — 개발 진행 가이드

> 1인 바이브코딩 프로젝트 | "무엇을 먼저 만들어야 하는가"를 순서대로 정리한 문서

---

## 전체 시스템 구조 (큰 그림)

이 플랫폼은 크게 3개 층으로 구성됩니다.

```
┌──────────────────────────────────────────┐
│  화면층 (사용자가 보는 부분)              │
│  농가 대시보드 / 모바일 앱 / 관리 화면   │
└─────────────────┬────────────────────────┘
                  │ 데이터 주고받기
┌─────────────────▼────────────────────────┐
│  서버층 (AI 계산 + 데이터 처리)          │
│  예측 서버 7개 + 수집·전처리 서버       │
└─────────────────┬────────────────────────┘
                  │ 저장·읽기
┌─────────────────▼────────────────────────┐
│  저장층 (데이터 보관 창고)               │
│  센서 DB / 파일 저장소 / 빠른 캐시 공간  │
└──────────────────────────────────────────┘
```

### 사용하는 주요 기술 모음

| 용도 | 기술 이름 | 쉬운 설명 |
|------|-----------|-----------|
| AI 모델 만들기 | PyTorch, XGBoost | AI가 학습하는 엔진 |
| 서버 만들기 | FastAPI | 화면과 AI를 연결하는 중간 서버 |
| 데이터 자동 수집 | Airflow | 정해진 시간에 데이터를 자동으로 가져오는 스케줄러 |
| 실시간 센서 연결 | MQTT | IoT 센서 데이터를 받아오는 통신 방식 |
| 시계열 데이터베이스 | TimescaleDB | 시간 순서대로 센서 데이터를 저장하는 데이터베이스 |
| 파일 저장소 | AWS S3 / NHN OBS | 사진·AI 모델 파일을 보관하는 클라우드 창고 |
| 빠른 임시 저장 | Redis | AI 결과를 빠르게 꺼내기 위한 메모리 캐시 |
| AI 실험 기록 | MLflow | 어떤 AI 모델이 얼마나 잘했는지 기록·비교하는 도구 |
| 데이터 버전 관리 | DVC | 데이터가 언제 어떻게 바뀌었는지 이력을 관리하는 도구 |
| 서비스 모니터링 | Prometheus + Grafana | 서버가 잘 돌아가는지 실시간으로 보여주는 모니터 |
| 프로그램 패키징 | Docker Compose | 여러 서버 프로그램을 한꺼번에 실행·관리하는 도구 |
| 화면 (웹) | React 18 + TypeScript | 대시보드 웹페이지를 만드는 프레임워크 |
| 화면 (앱) | React Native | iOS·Android 앱을 하나의 코드로 만드는 도구 |
| GPU 서버 | NVIDIA A10G | AI 모델 학습에 쓰는 고성능 그래픽 카드 |

## 개발 순서 한눈에 보기

> 아래 순서대로 만들어 나가면 됩니다. 앞 단계가 완성돼야 다음 단계로 넘어갈 수 있습니다.

```
1단계  인프라 & 개발환경 구축       (1~2주)   ← 가장 먼저, 토대 만들기
2단계  데이터 자동 수집 연결        (2~6주)   ← 데이터 흘러들어오게 만들기
3단계  데이터 정제 & 가공           (3~5주)   ← AI가 쓸 수 있도록 데이터 다듬기
4단계  병해 진단 AI (M5)           (4~10주)  ← 가장 빠른 성과, 먼저 출시
5단계  생육 예측 AI (M1)           (6~12주)  ← 핵심, 다른 AI들의 기반
6단계  생산량 + 수확시기 AI (M2·M3) (8~16주)  ← M1 완성 후 연결
7단계  API 서버 구축               (4~8주)   ← 화면과 AI를 연결하는 다리
8단계  농가 대시보드 베타 출시      (8~20주)  ← 농가가 실제로 쓰는 화면
9단계  매출 추정 AI (M4)           (12~20주) ← Phase 2 시작
10단계 에너지 절감 AI (M6)         (16~28주) ← Phase 2~3
11단계 운영 자동화                  (16~24주) ← AI 스스로 재학습
12단계 모바일 앱                    (16~28주) ← 스마트폰 앱
13단계 품질 예측 AI (M7)           (24~36주) ← 실측 데이터 쌓인 후
14단계 농가 확장 & 고도화           (30주+)
```

## 1단계. 인프라 & 개발환경 구축
**Phase 1 | 1~2주 | 가장 먼저 해야 할 일**

> 집을 짓기 전에 땅을 다지고 기초를 놓는 단계입니다. 이 단계가 없으면 아무것도 실행되지 않습니다.

### 서버 & 실행 환경
- GPU 서버 준비 (AI 학습에 쓸 고성능 컴퓨터)
- Docker Compose¹로 서버 프로그램들 한꺼번에 실행 설정
- NHN Cloud 또는 AWS에 서버 환경 구성 (국내 개인정보 규정 준수)
- GitHub Actions²으로 코드 바뀌면 자동 배포 설정

### 데이터 저장 공간 만들기
- **TimescaleDB**: 센서 데이터 저장용 데이터베이스 설치 및 테이블 구조 생성
  - 저장할 테이블 구조:
    - `센서기록`: 농가ID, 측정시각, 온도, 습도, CO₂, 일사량, EC, pH
    - `생육기록`: 농가ID, 작목, 날짜, 초장, 잎면적, 착과수, 건물중
    - `수확기록`: 농가ID, 작목, 수확일, 무게(kg), 등급
    - `단가이력`: 작목, 날짜, 경락가, 도매가
- **파일 저장소(S3)**: 원본 데이터 → 가공 데이터 → AI 모델 파일 순서로 분류 보관
- **Redis**: AI 예측 결과를 빠르게 화면에 전달하기 위한 임시 보관 공간

### AI 개발 도구 설치
- Python 3.11+ 및 AI 라이브러리 환경 설정
- **MLflow**: AI 모델 성능 기록·비교 서버 구축
- **DVC**: 학습 데이터가 언제 어떻게 바뀌었는지 이력 관리 설정

## 2단계. 데이터 자동 수집 연결
**Phase 1 | 2~6주 | 즉시 착수**

> 데이터가 없으면 AI를 만들 수 없습니다. 수집 파이프라인³을 먼저 열어 놓아야 합니다.

### 수집할 데이터 종류와 방법

| 데이터 | 어디서 | 무엇을 | 얼마나 자주 | 어떻게 |
|--------|--------|--------|------------|--------|
| 온실 센서 | 5개 농가 IoT 기기 | 온도·습도·CO₂·일사량·EC·pH | 10분마다 | MQTT⁴로 실시간 수신 |
| 농진청 생육 데이터 | 농진청 공개 API | 4개 작목 환경·생육·생산량 | 매일 오전 9시 | 스케줄러 자동 수집 |
| 시장 단가 | KAMIS 농산물유통정보 | 경락가·도매가 (과거 5년 포함) | 매일 오전 6시 | 스케줄러 자동 수집 |
| 기상 데이터 | 기상청 | 지역별 연간 기상 | 계절마다 | 파일 다운로드 → 변환 |
| 병해 이미지 | AI Hub | 딸기·토마토·참외 병든 작물 사진 | 최초 1회 | 다운로드 → 학습/검증/테스트 7:1.5:1.5로 분류 |
| 방울토마토 데이터 | WUR 네덜란드 연구소 | 방울토마토 생육 데이터 | 최초 1회 | 다운로드 → 국내 환경과 차이 분석 후 전처리 |

### 현장 데이터 추가 수집
- 수확 기록 표준 양식 농가에 배포 (날짜·무게·등급 기록)
- 데이터 문제 발생 시 신고 채널: 카카오톡 채널 운영
- Phase 3에 추가할 센서: 당도계(굴절당도계), 전력계(스마트전력계), 엽온센서

## 3단계. 데이터 정제 & 가공
**Phase 1 | 3~5주**

> 수집된 날 것의 데이터에는 오류, 누락, 이상값이 많습니다. AI가 제대로 배울 수 있도록 데이터를 다듬는 단계입니다.

### 데이터 정제 흐름

```
수집된 원본 데이터
    │
    ▼ 이상값 제거
    │   온도는 0~60℃ 범위 밖이면 제거
    │   습도는 0~100% 범위 밖이면 제거
    │
    ▼ 빈 값 채우기 (결측 보간⁵)
    │   30분 이내 빈 값 → 앞뒤 값으로 직선 보간
    │   30분 넘게 빈 값 → 비슷한 패턴의 주변 데이터로 채우기 (KNN⁶)
    │
    ▼ 시간 단위 통합
    │   10분 단위 → 시간 단위 → 일 단위로 합산
    │
    ▼ 시차 변수 만들기
    │   7일 전 값, 14일 전 값, 온도 누적합(GDD⁷) 계산
    │
    ▼ 값 범위 통일 (정규화⁸)
    │   작목별로 0~1 사이 값으로 변환 (비교 가능하게)
    │
    ▼ 학습용 / 검증용 / 테스트용 분리
    │   8 : 1 : 1 비율 (마지막 작기는 반드시 테스트용으로 고정)
    │
    ▼ S3 저장소에 버전 태그 달아서 보관
```

### 데이터가 부족할 때 보완 방법
- TOMGRO⁹ 또는 EnergyPlus¹⁰ 시뮬레이션으로 가상 데이터 생성
- 가상 데이터를 만들 때 온도는 ±2℃, 일사량은 ±20% 범위에서 변형
- TimeGAN¹¹으로 시계열 데이터 추가 생성

## 4단계. 병해 진단 AI (M5)
**Phase 1 | 4~10주 | 가장 먼저 출시 가능한 기능**

> AI Hub에서 이미 학습된 모델을 가져와 우리 작목에 맞게 추가 학습만 하면 됩니다. 가장 빠르게 농가에 보여줄 수 있는 기능입니다.

### 만드는 순서
1. AI Hub에서 병해 진단 AI 모델(EfficientNet-B4¹²) 다운로드
2. 딸기·토마토·참외 병해 사진으로 추가 학습 (작목당 200장 이상)
3. 환경 조건 기반 위험도 규칙 추가 (온도·습도가 일정 수준 넘으면 경보)
4. 처방 내용 자동 생성 (방제 시기, 예상 손실률)
5. 서버 컨테이너로 패키징 후 배포

### 입력 → 출력
| 입력 | 출력 |
|------|------|
| 스마트폰으로 찍은 작물 사진 | 병해 종류와 발생 확률 |
| 온도·습도 최근 측정값 | 방제 시기 권고 |
| | 예상 수확 손실률 |
| | 환경 위험도 신호등 |

### 출시 기준 (이 기준을 넘어야 실제 농가에 배포)
| 기준 | 목표 |
|------|------|
| 병해 감지 정확도 (F1¹³) | 88% 이상 |
| 병이 있는데 못 잡는 비율 (위음성¹⁴) | 5% 이하 |
| 전체 정확도 | 92% 이상 |

## 5단계. 생육 예측 AI (M1) ― 핵심 모듈
**Phase 1 | 6~12주 | 1순위**

> 다른 AI들(생산량·수확시기·품질)이 모두 이 모듈의 결과를 입력으로 사용합니다. 가장 공을 들여야 하는 핵심입니다.

### 학습 순서 (이 순서를 반드시 지켜야 합니다)

```
① 물리 모델 먼저 만들기
   └─ TOMGRO (토마토·방울토마토·참외용 작물 성장 수식 모델)
   └─ DSSAT CROPGRO-Strawberry (딸기용)
   └─ 국내 품종에 맞게 파라미터⁹ 수치 보정 (Optuna¹⁵ 사용)

② 네덜란드 WUR 데이터로 AI 기초 학습 (사전학습¹⁶)
   └─ LSTM¹⁷ 2겹 구조, 과적합 방지 Dropout¹⁸ 0.3 적용
   └─ 7일 전·14일 전 값, 온도 누적합 변수 포함

③ 우리 5개 농가 데이터로 추가 학습 (파인튜닝¹⁶)
   └─ 농가 1곳씩 빼고 학습, 빠진 농가로 검증 (Leave-one-out¹⁹)

④ 예측 신뢰구간 계산 (MC Dropout²⁰)
   └─ "이 예측이 80% / 95% 확률로 이 범위 안에 들어온다" 형태로 출력
```

### 입력 → 출력
| 입력 | 출력 |
|------|------|
| 온도·습도·CO₂·일사량·EC·pH | 초장·잎면적·착과수·건물중 예측값 |
| 7일 전·14일 전 같은 값들 | 생육 이상 점수 |
| 온도 누적합 | 80%·95% 신뢰 범위 |

### 출시 기준
| Phase | 정확도(R²²¹) | 오차율(MAPE²²) |
|-------|-------------|---------------|
| Phase 1 | 0.62 이상 | 15% 이하 |
| Phase 3 | 0.85 이상 | 12% 이하 |

## 6단계. 생산량 + 수확시기 AI (M2·M3)
**Phase 1~2 | 8~16주 | M1 완성 후 즉시 착수**

> M1이 "지금 작물 상태가 이렇다"고 알려주면, M2·M3가 "그러면 언제 얼마나 수확되겠다"를 계산합니다.

### M2 — 생산량 예측

| | 내용 |
|--|------|
| **방법** | XGBoost²³ + TOMGRO 물리모델 조합 |
| **입력** | M1 결과값 (잎면적·건물중·착과수), 누적 일사량, 정식 후 경과일 |
| **출력** | 주별 수확량 (kg/m²), 총 생산량 (kg), 증가·감소 방향 + 신뢰 범위 |
| **출시 기준** | Phase 1: 오차율 25% 이하, 방향 예측 정확도 70% 이상 |
| **데이터 부족하면** | TOMGRO 시뮬레이션 결과 사용 (±25% 오차임을 농가에 고지) |

### M3 — 수확시기 예측

| | 내용 |
|--|------|
| **방법** | 딸기·참외: 온도 누적합(GDD) + 생존분석²⁴ / 토마토: LSTM 시계열 |
| **입력** | 착과 확인일, 온도 누적합, M1 생육 상태 |
| **출력** | 수확 예정일, 신뢰 범위 (±일), 수확 확률 분포 |
| **출시 기준** | 딸기·참외: ±5일 이내 (Phase 1) → ±2일 이내 (Phase 3) |
| **데이터 없으면** | 문헌 기준 사용 (딸기 600~800 GDD, 토마토 착과 후 40~55일) |

## 7단계. API 서버 구축
**Phase 1 | 4~8주 | 모델 개발과 병행 가능**

> 화면(앱·웹)과 AI 사이를 연결하는 중간 서버입니다. 먼저 빈 연결 구멍만 뚫어 놓고, AI가 완성되면 하나씩 연결합니다.

### 구현 내용
- FastAPI²⁵로 REST API²⁶ 서버 구축
- JWT²⁷ 인증: 로그인 없이는 데이터 접근 불가
- 역할별 접근 제어: 농가 계정 / 관리자 계정 구분
- 7개 AI 모듈별 연결 엔드포인트²⁸ 구현
- Swagger²⁹ 자동 문서 생성

### AI 결과를 전달하는 표준 형식
```json
{
  "모듈": "M1",
```

## 11단계. 운영 자동화
**Phase 2 | 16~24주**

> AI가 오래 쓰이면 성능이 점점 떨어집니다. 자동으로 재학습하고 새 모델로 교체하는 시스템을 만듭니다.

### 자동 재학습 흐름
```
정기 실행: 매월 1회 자동
긴급 실행: AI 오차율이 기준치보다 5%p 초과하면 즉시

① 새 AI 학습 (챌린저³⁵)
② 현재 AI (챔피언³⁵)와 성능 비교
③ 새 AI가 더 좋으면 자동 교체 후 Slack 알림
④ 기준 미달이면 기존 AI 유지, 담당자에게 경고
```

### 이상 감지 알람

| 언제 | 어떻게 |
|------|--------|
| AI 오차율이 기준보다 5%p 초과 | 즉시 재학습 자동 실행 |
| 센서 데이터가 3일 연속 50% 이상 빈칸 | 현장 점검 알람 |
| API 응답이 2초 이상 걸릴 때 | 서버 자동 증설 |
| 병해를 한 주에 3번 이상 놓쳤을 때 | M5 긴급 재학습 |

| ³ | 파이프라인 (Pipeline) | 데이터가 수집 → 정제 → 저장 → 사용 순서로 흐르는 자동화된 처리 경로 |
| ⁴ | MQTT | IoT 기기(센서)에서 데이터를 가볍고 빠르게 전송하는 통신 규격 |
| ⁵ | 결측 보간 | 빠진 데이터 값을 앞뒤 값을 참고해서 채워 넣는 처리 |
| ⁶ | KNN (K-Nearest Neighbors) | "비슷한 상황의 데이터"를 찾아 빈 값을 채우는 방법 |
| ⁷ | GDD (Growing Degree Days) | 작물 생장에 필요한 온도 누적합. 온도가 높을수록 빠르게 쌓임 |
| ⁸ | 정규화 (Normalization) | 서로 단위가 다른 값들을 0~1 사이로 통일해 AI가 비교하기 쉽게 만드는 과정 |
| ⁹ | TOMGRO / 파라미터 | 작물 성장을 수학 수식으로 표현한 물리 모델. 파라미터는 모델 안의 조절 가능한 수치들 |
| ¹⁰ | EnergyPlus | 건물(온실)의 에너지 소비를 시뮬레이션하는 미국 에너지부 공인 프로그램 |
| ¹¹ | TimeGAN | 시계열 데이터(시간 순서 데이터)를 인공으로 생성하는 AI 기법 |
| ¹² | EfficientNet-B4 | 이미지 분류에 강한 경량 AI 모델. 병해 사진 분류에 적합 |
| ¹³ | F1-score | 정밀도(틀린 경보 없이 맞추기)와 재현율(빠짐 없이 잡기)의 균형 지표. 1에 가까울수록 좋음 |
| ¹⁴ | 위음성 (False Negative) | 실제로 병이 있는데 AI가 "정상"이라고 잘못 판단하는 오류 |
| ¹⁵ | Optuna | AI 모델의 설정값을 자동으로 최적화해주는 라이브러리 |
| ¹⁶ | 사전학습 / 파인튜닝 | 사전학습: 대량 데이터로 기초 학습. 파인튜닝: 기초 모델을 우리 데이터에 맞게 추가 학습 |
| ¹⁷ | LSTM (Long Short-Term Memory) | 시간 순서가 있는 데이터(온도 변화, 생육 변화 등)를 학습하는 AI 구조 |
| ¹⁸ | Dropout | 학습 중 일부 연결을 무작위로 끊어 AI가 특정 데이터에만 치우치지 않도록 하는 기법 |
| ¹⁹ | Leave-one-out 교차검증 | 농가 5곳 중 1곳씩 순서대로 빼고 학습한 후 빠진 농가로 검증하는 방식 |
| ²⁰ | MC Dropout | 학습 시에만 쓰는 Dropout을 예측 시에도 여러 번 적용해 결과의 불확실성을 수치로 나타내는 기법 |
| ²¹ | R² (결정계수) | AI 예측이 실제 값을 얼마나 잘 설명하는지 나타내는 지표. 1에 가까울수록 좋음 |
| ²² | MAPE (평균절대백분율오차) | 예측값이 실제값에서 평균적으로 몇 % 벗어났는지 나타내는 오차율 |
