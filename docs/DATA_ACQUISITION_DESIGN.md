# 6축 최적화 모델 업데이트를 위한 데이터 확보 설계

> 작성 2026-07-18 · 근거: 코드·아티팩트 실측(3개 서브에이전트 조사, 파일·라인 명시)
> 목적: "환경·양액·생육·병해·수확·수익 모델을 업데이트할 수 있나"에 대한 정직한 답 —
>       무엇이 재학습으로 풀리고, 무엇이 **데이터 없이는 불가**한지 구분하고,
>       각 병목을 여는 데 필요한 **데이터의 종류·규모·수집 설계**를 정량화한다.
> 관련: [MODEL_ENHANCEMENT.md](MODEL_ENHANCEMENT.md)(모델 성능 진단·고도화 로드맵, 2026-06-04) 의
>       "🟡 중기(데이터 기반)" 절을 대체·구체화한다. 중간보고서 제6장 제2·3절과 연동.

> ★ 튜닝으로는 안 된다 (2026-07-18 실측 확정):
>   파프리카·완숙 M2 하이퍼파라미터/모드 스윕의 순이득은 미미(≤0.03)했다. 모드 선택을
>   CV MAPE→CV R²로 바꾸면 전 작목이 monthly로 쏠려 R²가 급등하나(참외 -0.122→0.506) —
>   이는 신호가 아니라 **자기상관 신기루**다(SHAP 상위: yield_lag1·yield_ewm3(지난달 수확)·
>   month_sin/cos(계절모양)·farm_yield_hist_mean(농가정체성)뿐, 환경/경영 변수 0).
>   서빙/계획 시점엔 지난달 실측이 없어 예측력을 과장한다. 재현: `scripts/_tune_m2_experiment.py`.
>   → 진짜 지렛대는 코드 튜닝이 아니라 아래의 데이터 확보다.

## 0. 한 장 요약 — 병목의 성격별 분류

| 성격 | 축·모델 | 재학습으로 되나 | 무엇이 필요한가 |
|------|---------|:---:|-----------------|
| **A. 지금 데이터로 재학습 가능(이득 상한 낮음)** | 파프리카 M2(CV R² 0.076)·완숙토마토 M2(0.099) | △ | 피처·모델 튜닝. 표본은 있음(858·177) |
| **B. 실데이터 확보 시 필수 재학습** | 오이 stage3 매출(**합성 데이터**, CV MAPE 3.48 허수) | ○(데이터 후) | 실 농진청 매출·단가 데이터 |
| **C. 데이터 설계 문제 — 재학습해도 불가** | 환경 반응(CV R² −0.24~−1.39)·방울 M2(−0.257)·참외 M2(−0.122) | ✗ | 환경 처치 실험 / 표본 증대(설계 필요) |
| **D. 구조(코드) 문제 — 데이터 무관** | stage3 딸기·참외 매출 서빙 폴백 | ✗(재학습 아님) | 학습·서빙 피처 계약 재설계(코드) |
| **E. 모델이 아님 — 규칙/계수** | 양액 P1~P6·환경 처방·stage4 비용·출하시점 | — | 상수·밴드 검토(도메인 판단) |
| **F. 모델이 아직 없음** | 병해 이미지 진단(.pt 파일 부재) | — | 라벨 이미지 데이터셋 or 상용 API 키 |

**핵심**: 6축 중 데이터로 열리는 병목이 5개(B·C·F 전부 + A 일부). 이들은 우연이 아니라
**이암허브 과업①(소득조사 20개소)·환경 실증 실험**이 공급해야 하는 것과 정확히 겹친다.
즉 "모델 업데이트"의 실질 선행조건은 재학습 코드가 아니라 **데이터 수집 설계**다.

## 1. 수확최적화 (M2 수확량) — 표본이 판정을 가른다

### 현재 (pipeline/gates.py: CV_R2_MIN=0.20, CV_R2_FALLBACK=0.0)
| 작목 | CV R² | n_train | 판정 | 병목 |
|------|------:|--------:|------|------|
| 딸기 | 0.291 | 6427(monthly) | 적용 | — (충분) |
| 오이 | 0.386 | 61(annual) | 적용 | 표본 61로 취약 |
| 파프리카 | 0.076 | 858(monthly) | 조건부 | 설명력 부족 |
| 완숙토마토 | 0.099 | 177 | 조건부 | 설명력 부족 |
| 방울토마토 | −0.257 | 103 | 폴백 | 표본·신호 부족 |
| 참외 | −0.122 | 84 | 폴백 | 표본 84 · 피처 64(차원의 저주) |

### 필요 데이터
- **방울·참외**: annual 농가-연 표본이 근본적으로 작다. `train_stage2_yield.py` L582 —
  n<150이면 강력 피처(yield lag1/2/3·ewm3)를 **끈다**(과적합 방지). 즉 표본이 이 문턱을
  넘어야 학습 스크립트가 성능을 낼 수단을 켠다.
- **정량 목표**: 두 작목 각 **농가-연 ≥ 150** (현재 참외 84·방울 103). 과업①이 20개소를
  다년 축적하면 도달 가능. 단 "농가 수 20"이 아니라 "농가×연도 = 150"이 기준 —
  20개소를 **최소 3~4개 작기** 반복 관측해야 한다.
- **파프리카·완숙**(A군): 표본은 있으므로 데이터가 아니라 **피처·튜닝** 문제.
  지금 재학습 시도는 가능하나 조건부→적용 전환 보장 없음(정직하게 시도 후 무개선이면 유지).

## 2. 수익최적화 — 오차의 주범은 수확량이 아니라 단가

### 측정된 사실
- stage3 CV MAPE는 **오라클(실측) 수확량 전제**라 서빙 정확도가 아니다
  (`train_stage3_revenue.py` L357~389: `log_yield_annual`은 실측 관측치).
- 서빙에서 M2 예측 수확량이 들어가면 M2 오차가 그대로 전파. 방울·참외 M2가 폴백인 한
  매출도 그만큼 나빠진다 → **수익 정확도는 수확 정확도에 종속**.
- 매출 오차의 독립적 주범은 **단가 변동**(농가·시점별 CV 34~51%). 수확량을 완전히 알아도
  매출은 32~56% 오차(보고서 제3장·제5장).
- **오이 stage3 = 합성 데이터**(`cucumber/stage3_meta.json`: "합성 데이터 기반 — 실 농진청
  데이터 수집 후 재학습 권장", cv_mape 3.48은 허수).

### 필요 데이터
- **오이 실 매출·출하 데이터**(B군): 합성 → 실측 교체. 과업①의 출하·매출 항목이 직접 공급.
- **농가별 실 경영비**(stage4는 계수 공식·비-ML): 현재 `income_survey.json` 계수 기반.
  농가별 실제 비용이 없어 **소득(=매출−비용) 검증이 불가**. 과업①의 13항목 비용 상세가
  이걸 연다 — 이때 stage4는 "계수 갱신"이지 재학습이 아니다.
- **단가 이력 누적**(출하시점): `shipping_timing`은 n≥1,000 월만 채택(소표본 낙관편의 차단).
  KAMIS 이력이 쌓일수록 신뢰 월이 늘어난다 — 재학습이 아니라 **누적**의 문제.

## 3. 환경최적화 — 관측 데이터로는 인과가 안 나온다(★ 재학습 무의미)

### 측정된 실패 (out/_env_response.json)
| 작목 | n | CV R² | 반응폭%(온도/습도/CO₂) |
|------|--:|------:|------------------------|
| 딸기 | 579 | −0.493 | 6.3 / 19.5 / 75.7 |
| 오이 | 74 | −0.866 | 1.1 / 32.3 / 22.4 |
| 파프리카 | 313 | −1.202 | 21.4 / 11.3 / 28.9 |
| 완숙토마토 | 649 | −0.242 | 37.0 / 10.9 / 3.1 |
| 방울토마토 | 261 | −1.385 | 22.4 / 26.8 / 11.5 |
| 참외 | — | 산출실패 | — |

- 전 작목 CV R² 음수 = 평균 예측보다 못함. **하이퍼파라미터가 아니라 데이터 성격의 문제**:
  같은 농가가 환경을 거의 안 바꿔(관측), "농가 실력"과 "환경 효과"가 분리 안 됨(교란).
- 딸기 온도-수확 상관 −0.274(겨울 촉성 작기 탓 부호 반전). 농가 고정효과 제거 후
  방향은 정상화되나(+0.12~0.13) **크기가 매우 작다**.
- 1분 원천(2021 딸기 213,188행)으로 생리 피처를 정교화해도 **인과는 안 생긴다**
  (`build_env_features_daily.py` L25: "피처를 만들었다고 인과가 생기지는 않는다").

### 필요 데이터 — 관측이 아니라 **실험**
관측 데이터로는 ∂수확량/∂환경을 인과로 주장할 수 없다. 유일한 해법은 **처치 배정 실험**:
- **설계**: 같은 작목·지역에서 환경 처치(예: 주간 목표온도 2~3구간, VPD 밴드 2구간)를
  **농가·구획에 배정**하고 반복. 나머지는 최대한 통제(작기·품종·정식일 정렬).
- **필요 표본 산정법**: 검출하려는 효과 크기 기준 검정력 분석.
  관측 상관이 부분상관 0.12~0.19(작은 효과, Cohen f² ≈ 0.015~0.04)로 작으므로,
  작은 효과를 유의하게 검출하려면 처치당 반복이 커야 한다. 예: 3처치 일원배치에서
  작은~중간 효과(f²≈0.06) 검출(α=.05, power=.8)에 총 **≈150~250 관측**(처치·반복 조합).
  → 20개소를 처치에 배정하고 **다년·다구획 반복**으로 이 규모를 만든다.
  ※ 위 수치는 방법(검정력 분석) 예시다. 확정 표본은 목표 효과크기·분산 확정 후 계산한다.
- **주의**: 이 실험 설계가 보고서 제6장 "환경 실증" 및 line 561 「기재 필요」의 실체다.

## 4. 양액최적화 — 모델이 아니다(규칙/제어기)

### 현재 (전부 규칙·공식, ML 0개)
- P1~P6 관수 Period: `components/data.js` PERIODS(Grodan/Priva 매뉴얼 상수),
  `getCurrentPeriod()`는 시각 폴백 판별(일사적산 우선 원칙은 데이터에 기술되나 미구현).
- G3 정상범위(급액EC 2.5~3.5·pH 5.5~6.5 등): 하드코딩 상수(Priva/Grodan).
- Priva 스케줄: ET₀(Hargreaves)·Kc·PI 제어기 — 결정론적.

### "업데이트"의 의미
- 재학습 대상 없음. **상수·밴드·Kc 조정**은 도메인 판단이지 데이터 학습이 아니다.
- 단, 데이터가 열어줄 수 있는 것: 관수 입력이 누적되면(POST /irrigation) **양액→수확** 반응을
  실험 설계 하에 검증할 수 있다 — 이는 3절(환경 실험)과 같은 방법론(처치 배정)이 필요하다.

## 5. 생육최적화 — 수확량의 매개변수이지 독립 서비스가 아니다

### 측정된 사실
- Stage1(환경→생육)은 학습·아티팩트 저장되나 **사용자 대상 라이브 생육예측 엔드포인트 없음**
  (진단용 CV R² 숫자로만 노출). Stage2는 **CSV 실측 생육값**을 입력 피처로 씀(예측값 아님).
- Stage1 성능: 딸기 0.284(PASS) / 오이 0.095 / 파프리카 0.066 / 완숙 −0.053 / 방울 −0.174.
  게이트가 CV R²≥−0.25로 **완화**돼 있어 "PASS"가 예측력 양호를 뜻하지 않음.

### 필요 데이터
- **토마토·방울 생육 CSV 보강**(MEMORY에 이미 재학습 대기로 표기): 실측 생육 시계열.
- 생육을 **독립 의사결정 대상**으로 쓰려면(예: "지금 초장이 목표 대비 미달 → 조치"),
  생육 목표 곡선(작목·작기별 표준 생육 궤적)의 실측 근거가 필요 — 과업① 생육 항목.

## 6. 병해최적화 — 학습된 이미지 모델이 존재하지 않는다

### 측정된 사실
- `models/artifacts/m5_efficientnet.pt` **디스크에 없음** → 이미지 경로는 stub(고정확률)
  또는 외부 상용 API(Plant.id, 키 필요) 폴백. 모델 대시보드도 자백:
  `"grade":"⚠️ 이미지모델 미구축"`(farmer.py L2143).
- 실서빙 병해 진단 = **환경규칙(M5 rule v2, 8종 병해 임계값)** + **BM25 지식베이스 검색**
  (교재 735청크). 임계값은 농진청/WUR 지침 계수(실측 라벨 검증 없음).
- PLS(농약안전) 가드는 **LLM 프롬프트 지침**(ai_chat.py L172)이지 약제DB 대조 강제 아님.

### 필요 데이터
- **라벨링된 병해 이미지 데이터셋**(작목·병해·중증도): 이미지 분류 모델의 존재 전제.
  없으면 상용 API 키(`PLANT_ID_API_KEY`)로 대체 — 이 경우 학습이 아니라 연동.
- 환경규칙 임계값을 데이터로 검증/보정하려면 **병해 발생 실측 라벨 + 당시 환경 로그**의
  매칭 데이터 필요(현재 없음).

## 7. 종합 — 무엇을 언제 하나

### 지금(데이터 없이) 가능한 것
1. **파프리카·완숙 M2 튜닝 시도**(A군) — 이득 상한 낮음, 정직하게 시도·무개선 시 유지.
2. **규칙 축 검토**(양액·환경·비용 계수) — 도메인 판단 확보 시.

### 데이터가 열어주는 것(과업①·환경실험 선행)
3. **방울·참외 M2**: 농가×연도 ≥150 축적 → 강력 피처 활성.
4. **오이 stage3**: 합성 → 실측 교체.
5. **stage4 비용·소득 검증**: 농가별 13항목 실비용.
6. **환경·양액 최적화**: 처치 배정 실험(관측으로는 영구 불가).
7. **병해 이미지 모델**: 라벨 이미지 데이터셋.

### 데이터와 무관한 코드 작업(별도 판단)
8. **stage3 딸기·참외 서빙 폴백**(D군): 학습·서빙 피처 계약 재설계.
   단 현재 폴백은 **의도된 안전장치**(test_profit_wiring.py가 명시)이므로,
   Ridge 강제 전에 그 보정이 단순 곱셈보다 실제로 나은지부터 검증해야 한다.
