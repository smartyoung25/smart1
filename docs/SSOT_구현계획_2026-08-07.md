## Phase 1 — 수확량 SSOT (§B) ★ 핵심·선결
**쟁점**: `predict_yield_bounds`(35, raw ML) vs `m2_yield.predict_yield`(15, MAPE 블렌딩). 둘 다 "kg/m²·seasonal" 주장 → **단위·블렌딩 진위 규명 먼저**.
1. **조사**: stage2 산출이 monthly인지 seasonal인지 확정(m2_yield는 yield_kg_m2 / yield_kg_m2_monthly 구분, bounds는 미구분). 오이 MAPE 32.9<35인데 블렌딩이 35→15로 끌어내린 이유(RDA 오이 baseline·게이트) 추적.
2. **단일 함수 신설**: `model_loader.get_yield_forecast(crop, env, area, farm_id)` →
   `{yield_kg_m2_season, yield_kg_season, yield_kg_m2_monthly, q10, q90, confidence, mape, source}`.
   - 점예측 권위 = `m2_yield.predict_yield`(블렌딩·게이트 보유).
   - 구간 = `predict_yield_bounds`의 q10/q90을 **점예측 중심으로 스케일 정렬**(비율 유지).
3. `get_harvest`·`get_revenue`·`get_erp_realtime`가 이 함수만 호출. 기존 3경로 제거.
4. **검증**: farm_001 `/harvest.yield_kg_forecast == /revenue.yield_kg_forecast == /erp yield`.

## Phase 2 — 단가 SSOT (§C)
1. 권위 = `get_price_with_fallback(crop)`. `erp_calculator._get_kamis_price` → 이 함수 위임.
2. 채널 2분리: `price_individual`(KAMIS 도매)·`price_pool`(도매시장 정가). 응답·화면에서 "채널별 예상가"로 표기, "가입만으로 +N%" 프레이밍 제거(G6-3·C12-2).
3. **검증**: `/revenue.kamis_price == /erp market_price`(동일 작목 동일값).

## Phase 3 — 매출 파생 (§D)
1. `get_revenue`: `revenue = yield_kg_season × price`(Phase1·2 산출). `predict_revenue_per_m2` 금액경로 **표시 제거**(원하면 `revenue_ml_crosscheck` 필드로만 유지).
2. `whatif`(1328)도 동일 파생식으로 통일(델타 일관).
3. **검증**: `predicted_revenue == round(kamis_price × yield_kg_forecast)` — 캡션 곱 일치(C3-B 소멸). kg마진 ≤ 단가(C5-1 소멸).

## Phase 4 — 비용 시즌화 (§E)
1. `_compute_costs` 반환에 `cost_season_krw`(= cost_per_m2 × area × season_months) **추가**(기존 cost_per_m2·total_cost_krw는 유지 — 6곳 호환).
2. `get_revenue`·`get_erp_realtime`·c5 소비 지점만 `cost_season`으로 매출(시즌) 대비. 소득률·마진 = revenue_season vs cost_season.
3. 현실성 가드: 마진 >85% 시 응답에 `margin_warning=true` + 화면 "데이터 확인" 배지.
4. **검증**: farm_001 마진이 현실권(오이 40~55%)인지. (참고: G4-1 수정 후 /erp는 이미 +44%.)
