## 병해충 예찰 → G5/F6 (파이프라인 완성, 데이터 적재 대기)
- `scripts/import_real_pest.py` + `GET /field/pest` + `_REAL_PEST_CACHE` 완성.
- 제주 감귤 매칭 시 `pest_survey_real`(더뎅이병·궤양병·검은점무늬병·진딧물·깍지벌레 발병률), 비제주 `none`(룰기반 유지).
- **제약**: 예찰 parquet은 연도별 ~30KB 소용량이라 Drive MCP가 **인라인 반환**(디스크 미저장) → 본 환경에서 디코딩 불가.
  토양·필지·소득조사는 260KB↑라 자동 저장되어 디코딩됨. 파일을 디스크에 두고 `python scripts/import_real_pest.py <parquet>` 실행 시 즉시 활성(현재 `pending_import` graceful).

## 감귤 생육 → M2 재학습 (현 데이터로 불가 — 사유 명시)
- 생육조사(type=fruit)는 **착화율·화기탈락·화수·노엽수**(개화·착과 지표)만 보유, **수확량(M2 학습 타깃) 없음**.
- 소득조사에 생산량(prdv_qty)이 있으나 두 익명 데이터셋을 잇는 **농가 공통키 부재** → 직접 조인·재학습 불가.
- 단위감귤 수확량은 소득조사 11,061kg/300평이나 **단위(표준면적) 해석 모호** → yield 모델 직접 override는 보류(오삽입 위험). C9 벤치마크(소득률·수취가, 단위안전)에는 이미 반영됨.
- 올바른 재학습 경로: 농가단위 **생산량 시계열(출하량/소득)** + 생육·환경 피처 조인 학습. ERA5 실측 확보 후 진행(기존 backlog).

### M2 재학습 실착수 시도·검증 (2026-06-09)
소득조사(노지감귤 102농가)로 단위수확량 산출을 실제 시도 → **신뢰성 미달로 주입 보류**:
- yield = prdv_qty / 면적, 면적 컬럼 3종 모두 검증:
  · srvar_tot_sqm → 중앙값 1.09 / ar1_sqm → 1.32 / mcrp1_ar_sqm → 0.81 kg/m²
- 감귤 노지 통상 단수(~2.5 kg/m²) 대비 **일관되게 낮고 표본 분산 큼** → 생산량이 소득기준 가공·면적정의 불일치 추정.
- 결론: 잘못된 yield(0.8~1.5) 주입은 모델 왜곡 → **주입하지 않음**(현 placeholder 10.0 유지, C9는 단위안전 지표만 사용).
- 유효 재학습 입력: **작목별 실재배면적 매칭 생산량 + 환경(기온·일사) 피처**의 농가/지역·작기 시계열. 확보 시 M3 GDD·M2 stage2 파이프라인에 편입.

## 주입 불필요/불가
| 항목 | 사유 |
|------|------|
| **기상(제주 AWS)** | F3 기상은 이미 LIVE(KMA ASOS + Open-Meteo). AWS 과거 관측은 실시간 예보에 미반영 — 주입 가치 낮음 |
| **위성 NDVI** | 폴더에 위성 API/타일 없음. `SATELLITE_NDVI_URL` 키 주입 시 프록시→sentinel-2 전환(구조 완비) |
| **LLM·알림** | 데이터셋 무관. `.env` 키(`ANTHROPIC_API_KEY`·`SLACK_WEBHOOK_URL`·`COOLSMS_*`) 필요 |

## 추가 주입 가능(미적용)
감귤 생육조사·소득조사·디지털트랩(예찰)·도매시장 경매 등 — 작황/경영/병해/시세 정밀화에 활용 가능.
대용량 parquet은 `data_real/`(gitignore)에 받고 importer로 집계분만 `api/data/real/`에 적재.
