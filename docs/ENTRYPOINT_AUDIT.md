# 메뉴 진입점 감사 (Entry-Point Audit)

> 목적: 41화면 중 "메뉴(네비게이터·드로어·맥락 허브)에서 진입할 수 없는" 화면을 전수 탐지·개선.
> 방법: 화면 간 실제 링크(href/location.href/template)로 그래프 구성 → 허브(c3·g1·f1)+드로어+네비게이터에서 BFS 도달성 계산.

## 1차 발견 (개선 전)

| 화면 | 문제 | 자연 진입처(있어야 할 곳) |
|------|------|--------------------------|
| c13_chat | **막다른 화면** — 하단탭 없음 + 헤더 메뉴 없음 → 탈출 불가 | 헤더 ≡ 메뉴(드로어) |
| c11_pool_join | 맥락 진입 0 — 네비게이터에만 존재 | c12_joint(공동출하 운영)→가입 |
| c6_learning | 맥락 진입 0 | c7_reward(보상)↔학습기여 폐루프 |
| c8_interop | 맥락 진입 0 | c16_equipment(기자재·이기종) 자매화면 |
| c2_consent | 맥락 진입 0 (헤더 '‹메뉴'만) | 드로어 + 온보딩(c1) |

### 오탐(실제 도달 가능 — 수정 불요)
- **c20_report**: `location.href=\`c20_report.html?region=...\`` (템플릿+쿼리) 형태라 단순 정규식 미검출. c20_cluster_admin에서 정상 진입.
- **intro/overview/flow**: 랜딩 계층 — intro CTA·네비게이터에서 진입.

## 개선 (이번 배치)

1. **c13_chat** — 헤더에 ≡ 메뉴 버튼 추가 → `KaasaData.openMenu()`(드로어). 막다른 화면 해소.
2. **c12_joint** — '진행 중인 Pool' 헤더에 `＋ 공동출하 가입`(→c11) 버튼.
3. **c7_reward** — 상단에 `내 학습 기여 현황 보기`(→c6) 카드 (데이터→학습→보상 폐루프 가시화).
4. **c16_equipment** — `이기종 연동 표준·상호운용 안내`(→c8) 진입 카드.
5. **components/data.js** — 드로어 빠른이동에 `c2_consent(데이터 활용 동의)`·`c19_capability(역량)` 추가.
6. **components/data.js** — `window.KaasaData = KaasaData` 전역 노출(인라인 onclick에서 드로어 호출 보장).

→ 재감사 결과 **맥락+드로어 진입점 없는 화면 0건**. 콘솔 에러 0건.

## 비판적 반영 — 구조적 한계 & 향후 통합

1. **진입점이 "평면 네비게이터(/smartos)"에 과의존**: 네비게이터엔 38/41이 있으나, 실제 농가 동선(허브→세부)에서 빠진 화면이 위 5건이었음. 신규 화면 추가 시 *반드시 자연 허브에도 링크* 하는 규약 필요.
2. **드로어 ≡가 하단탭에만 바인딩**(`_bindMenuTab`): 하단탭 없는 단독 화면(c13류)은 자동으로 탈출구가 생기지 않음. → 향후 `data.js`가 **헤더에도 ≡ 메뉴를 자동 주입**하도록 일반화 권장(현재 c13만 수동 추가).
3. **감사 자동화 부재**: 본 감사는 1회성 스크립트. → CI/배포 전 `링크 그래프 BFS 도달성 == 41` 검사를 `scripts/`로 상시화 권장.
4. **링크 표기 불일치**: `href`, `location.href`, 템플릿 리터럴+쿼리스트링 혼재 → 정적 분석 오탐 유발. 진입 헬퍼(`KaasaData.go(screen, params)`) 단일화로 통일 권장.
