## 1. 최상위 이슈 — 경제모델 파편화

### 1.1 증상: 같은 farm_001 오이가 화면마다 다름

| 지표 | 홈/c5/c6/f7/c12 라인 | g4 라인 |
|------|---------------------|---------|
| 작목 | 오이 (`_require_farm`) | **딸기** (`get_farm_meta` 깨짐) |
| 수확량 | 18,000kg(/revenue)·42,005kg(/harvest) | 42,005kg |
| 시세 | 1,690원/kg (KAMIS) | 8,500원/kg (딸기 폴백) |
| 매출 | 6,106만원 | 35,704만원 |
| 손익 | **+95% 흑자** | **−18% 적자** |

### 1.2 4개 독립 근원

1. **수확량 3중 소스** — `predict_yield_bounds`(model_loader.py:434, 35kg/m²) / `m2_yield.predict_yield`(m2_yield.py:248, 15kg/m²) / `predict_revenue_per_m2`(model_loader.py:350, 암시 ~30kg/m²). 동일 M2 아티팩트, 서로 다른 래퍼가 다른 값 반환.
2. **매출 디커플 (C3-B)** — `/revenue`가 `predict_revenue_per_m2`(원/m²/월 × 면적 × 작기개월, farmer.py:1078-1088)에서 산출. 함께 실어보내는 `kamis_price(1690)·yield(18000)`와 곱 관계 아님 → 1,690×18,000=3,042만 ≠ 61M. UI 캡션 "단가×수량"이 값과 불일치.
3. **월/시즌 단위 혼용 (C5-3)** — 비용은 월(erp_calculator.py `*_per_m2_month`, `total_cost_per_m2` 월값), 매출은 시즌(farmer.py:1083 `× season_months`). 월비용 ÷ 시즌매출 = 소득률 95%(비현실)의 직접 원인.
4. **깨진 import (G4-1)** — `from api.data_access import get_farm_meta` (farmer.py:2860). `api/data_access.py` 모듈 부재·`get_farm_meta` 정의 전 repo 0건. 매번 ModuleNotFoundError → `except: meta={}` → crop="딸기"·area=1200 고정. 전 농가 `/erp/realtime`이 딸기로 계산.

### 1.3 파급/증거 화면

- **C5-1**: kg당 마진 3,217 > 판매단가 1,690 (음수 원가 의미) — C3-B의 물리적 표출.
- **G6-1/G6-2**: 한 화면에 42,005kg vs 18,000kg 병존, 매출 3,042만(시나리오·정확) vs 6,106만(수익성요약) 자기모순.
- **F7-1**: 노지 필지합 5,490만 vs 총계 6,106만, 노지 무 화면에 온실 오이 매출 노출.
- **C12-1**: 공동출하 정산 총매출이 개별 /revenue값 → 정산액 616만원 과대.
- **C25-4**: c25 효율성 "벤치 하위 1%ile" vs c5 "소득률 95% 목표달성" — 정반대 평가.

### 1.4 권고 수정 방향 (§SSOT 설계 별도)

(a) 수확량 SSOT 1개로 통합 · (b) 매출 = SSOT수량 × 단가 파생 · (c) 비용 ×season_months 시즌화 · (d) `get_farm_meta` 제거 후 `_require_farm` 통일.

## 6. 경제모델 SSOT 설계 (권장)

**원칙**: 작목·수확량·단가는 각각 **단일 권위 함수**. 매출은 **항상 파생**(수량×단가). 모든 값 **시즌 기준** 통일.

### A. 작목/메타 — 단일 리졸버  ✅ 적용완료(G4-1)
- 권위 `_require_farm(farm_id)`. `get_farm_meta` 경로 삭제. 전 엔드포인트 통일.

### B. 수확량 — 단일 함수
- 문제: `predict_yield_bounds`(35) vs `m2_yield.predict_yield`(15) 두 래퍼 불일치.
- 설계: **점예측 권위 = `m2_yield.predict_yield`**(MAPE 블렌딩·게이트·정직지표 보유). `predict_yield_bounds`는 q10/q90 구간만 제공하되 **점예측 중심으로 스케일 정렬**. `/harvest`·`/revenue`가 동일 함수 호출.
- 반환 단위 명시: `yield_kg_season`·`yield_kg_m2_season`·`yield_kg_m2_monthly`.

### C. 단가 — 단일 함수
- 권위 `get_price_with_fallback(crop)`. erp_calculator `_get_kamis_price` 위임/삭제.
- 채널 명시: `price_individual`(KAMIS 도매) vs `price_pool`(도매시장 정가) **2채널**. "가입만으로 +80%" 제거 → "채널별 예상가" 비교.

### D. 매출 — 항상 파생
- `revenue_season = yield_kg_season × price_per_kg`. `predict_revenue_per_m2` 금액경로는 표시값에서 제거(교차검증용만). → **C3-B 소멸**(캡션↔값 항상 일치).

### E. 비용 — 시즌화
- `cost_season = erp_calculator.total_cost_per_m2(월) × season_months`. 응답에 `cost_monthly`·`cost_season` 명시. 소득률·마진은 `revenue_season` vs `cost_season`로만. → **C5-3 소멸**.
- 현실성 가드: 마진 >85% 시 "데이터 확인" 플래그.

### F. 단일 계약
- `/farms/{id}/economics` 하나가 권위 {crop, yield, price, revenue, cost, margin, confidence} 반환. `/harvest`·`/revenue`·`/erp/realtime`은 얇은 뷰로 수렴 or deprecate. 홈·c5·c6·g4·g6·f7·c12가 동일 숫자 참조.

**수용 기준**: 수정 후 farm_001에서 전 화면 수확량·매출·마진이 **단일값 일치**.

- **핵심 확인**: m2_yield의 `yield_kg_m2`는 stage2+RDA클리핑 값으로 **season_months와 독립**(models/m2_yield.py:332). season은 비용 시즌화·monthly 파생에만 영향 → season 축소 시 수확량·매출 불변, 비용만 정합.

- **c5 배너 정정**: c5_erp.html:320 `_cost`를 costs.total_cost_krw(월) → revenue.predicted_cost_krw(시즌)으로. 구: 월비용÷시즌수확량 → kg원가 176·소득률 90% 왜곡. 후(오이): kg원가 878·소득률 48% (하단 수익성지표와 일치).
- **검증**: 오이 /revenue 마진 16.9%→**48.1%**(RDA정합), 수확량·매출 불변, 방울·딸기·완숙 side-effect 0. pytest 12F/10P(회귀0).

## 13. VPD 밴드 개념 분리·통일 (완료, SW v92)

- **결론**: VPD는 **두 개념**이 존재하며 이를 라벨로 명확 분리(값 강제통합 대신). 프런트 '적정대'는 이미 0.8~1.2로 통일돼 있었음.

  - **전략표 단계별 목표 = climate_plan** (g2 전략표, 0.5~0.76 등) — 유지(별개 개념).
