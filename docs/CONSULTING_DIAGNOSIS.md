# 현장컨설팅 종합진단 (C17 확장)

스마트농업 **현장컨설팅 체크리스트·결과보고서**를 벤치마킹하여, C17 시스템 진단을
인프라 성숙도 5영역에서 **현장컨설팅 6대 영역(센서·구동기·재배·경영노동·유통·데이터)**으로 확장.

## 벤치마킹 출처 (실문서)
| 문서 | 활용 |
|------|------|
| RDA/이암허브 **스마트농업 현장컨설팅 체크리스트(2024-08-13)** | 6대 영역 분류 + 항목(센서 외부기상/내부환경, 환기·냉난방·스크린·양액·원수, 생육단계, 데이터, 유통) |
| **스마트농업 통합관제 지역대표농가 현장컨설팅 최종결과보고서** | 진단 형식(사전진단→총평→농가별 개선방향=처방) |
| 소득333 프로젝트 농가 사례(안성·고양·가평) | 컨설팅 희망분야(생산기술·시설공정·환경개선·상품화·판로) |

## 6대 도메인 진단 (`GET /api/farms/{id}/diagnosis`)
| 도메인 | 진단 근거(실데이터) | 처방 딥링크 |
|--------|--------------------|------------|
| 📡 센서 계측 | 표준변수 매핑(온습도·CO₂·EC·pH·배액·일사·외부기상 12종), 핵심 5종 결측 시 상한 | c16_equipment |
| ⚙️ 구동기·제어 | 환기·보온냉난방·스크린·양액 4그룹별 자동제어 명령 연동·장비등록·캘리브레이션 | g2_env / g3_period / c16 |
| 🌿 재배·생육 | 배액률 20~30% 근접도, 월 생육측정 건수 | g3_period / g4_growth |
| 📋 경영·노동 | 운영등급 + 작업이행(관수·방제·환경·수확) 건수 → 적기성·노동효율 | c3_home / /smartos |
| 🚚 유통·판매 | 영업이익률, 공동출하 기록 → 판로 다변화 | c12_joint |
| 🗂️ 데이터·연동 | 월 이행기록 + 표준변수 매핑 → 재학습 임계 | c14_report |

각 도메인 = **점수(0~100) + 진단 findings + 처방 decisions**.
`summarize()`가 점수 낮은 도메인의 danger>warn>info 처방을 **ROI 우선순위**로 정렬 → `priority_decisions`.

## 의사결정 폐루프
C17 처방 카드 → `[조치하러 가기]`(해당 화면 딥링크) + `[기록]`(RecordSheet → POST /activity).
→ 진단 → 처방 → 이행 → 축적 → 재학습의 폐루프 연결.

## 핵심 파일
- `api/services/consulting_diagnosis.py` — 도메인 진단 엔진(체크리스트 분류 인코딩)
- `api/routers/farmer.py /diagnosis` — domains·priority_decisions 추가(기존 scores 유지)
- `screens/c17_diagnosis.html` — 6대 영역 카드 + 우선순위 처방 + 원탭 기록

## 현장 문진 체크리스트 (C18) — 텔레메트리 외 항목 보강
센서로 못 보는 항목(원수·필터·RO·유황훈증·공조기·병해충·인증·판로 등)을 컨설턴트/농가가 직접 점검.
- `api/data/diagnosis_checklist_schema.json` — 6도메인 30항목(RDA 체크리스트 인코딩)
- `GET/POST /diagnosis/checklist` — 응답 저장(`data/diagnosis/{farm}.json`)
- `screens/c18_checklist.html` — 항목별 양호/주의/불량/해당없음 + 메모, 진행률
- 블렌딩: `_blend_checklist()` 가 도메인 점수를 텔레메트리:현장 = 50:50 으로 혼합,
  **불량→danger 처방 최상위 / 주의→warn 처방** 자동 생성(기록 kind=consult)
- 검수: 양액 불량·병해충 불량 입력 시 재배 75→38, "[현장] 병해충…" danger 처방이 1순위로 승격

## 데이터 정직성
텔레메트리가 없으면 허위 점수 대신 **'점검필요(체크리스트)'** 항목으로 노출.
(예: 장비 미등록 → "구동기 보유현황 점검필요", 배액 데이터 없음 → "배지저울 도입 권장")
